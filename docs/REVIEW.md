# レビュー観点（レビュー用サブエージェント向け）

レビュー担当はコードを書き換えない。指摘を重大度付きで返す。

1. 仕様適合: docs/tasks/Txx.md の「作るもの」「完了条件」をすべて満たすか。SPEC/ER との食い違い。
2. 動作確認: 完了条件のコマンドを自分で実行し、結果を記録する。
3. Windows 互換: パス（pathlib）、改行、シェル依存、PowerShell/バッチの構文、文字コード（日本語メッセージの文字化け）。
4. 正しさ: 境界条件、例外処理、リソース解放（ファイル、DB セッション、GPU メモリ）、並行処理。
5. テストの質: 重要な振る舞いを本当に検証しているか。テストが常に通るだけの形になっていないか。
6. 安全: 外部公開しない前提（127.0.0.1）、パス操作の脆弱性、秘密情報。
7. 保守性: 後続タスクで拡張しやすいか（stem 種類の追加がデータだけで済むか等）。

出力形式:
- 判定: 合格 / 条件付き合格 / 差し戻し
- 指摘一覧: [重大/中/軽微] ファイル:行 — 内容 — 修正案
- 実行したコマンドと結果の要約
