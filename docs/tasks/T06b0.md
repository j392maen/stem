## 背景（2026-10-03 のユーザーの iPhone 診断）
- 端末: iPhone の Chrome（iOS 26.6.2、WebKit）。Opus/WebM・AAC・MP3・FLAC・WAV はすべて decodeAudioData できた。AudioWorklet・Media Session・ManagedMediaSource はある。Web Push は無い（ホーム画面から開いていない）。
- **Web Audio は消音モード（本体の消音スイッチ）だと画面がついていても鳴らない。ロックすると止まる。**
- **`<audio>` 要素は消音モードでも鳴り、ロックしても鳴り続ける。**
- 今の再生エンジンはすべて Web Audio なので、iPhone では消音モードで音が出ない。T06b（iPhone 向けの再生）の作り方を決めるため、次の方法を実機で比べる。

## 作るもの（診断ページ `#/diag` に「iPhone 再生の実験」の欄を追加）
それぞれ「鳴らす」ボタンを押すと、数十秒のテスト音（簡単なメロディやクリック。耳で分かるもの）を鳴らし、ユーザーが「消音モードで鳴ったか」「ロック中も鳴り続けたか」を選んで記録する（既存の lock_tests と同じ形で `POST /api/diag` に送る）。自動で取れる値（AudioContext の state の変化、currentTime の進み、visibilitychange の時間など）も一緒に記録する。

1. **A: audioSession**: `navigator.audioSession` があれば `type = "playback"` にしてから Web Audio で鳴らす（無ければ「この端末には無い」と表示して記録）。
2. **B: 無音の `<audio>` を一緒に鳴らす**: 無音（または聞こえないほど小さい）の短い音声をループする `<audio>` を再生してから、Web Audio で鳴らす。
3. **C: Web Audio の出力を `<audio>` に流す**: `createMediaStreamDestination()` の stream を `<audio>.srcObject` にして再生する（Web Audio の音を `<audio>` 要素から出す）。
4. **D: 参考 `<audio>` だけ**: 既存の element テストと同じ（比較用）。
5. 各実験で Media Session（`navigator.mediaSession.metadata` と再生・一時停止のハンドラ）を設定し、ロック画面に曲名と操作が出るかも記録できるようにする。

- 画面の説明は日本語で、「本体の消音スイッチを ON にしてから押す」「押したら画面をロックして 10 秒待つ」など、手順を短く書く。ユーザーの好みのデザイン（暗い DJ 風、差し色は赤系）。
- 実験の結果は `GET /api/diag` で監督役が読める形にする（既存のまま）。
