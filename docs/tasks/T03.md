# T03 取り込み（ファイル・URL）

ブランチ: `task/T03-import`（main から作成）
前提資料: `docs/SPEC.md`（3章 URL 取得、8章 理由コード）, `docs/ER.md`（TRACK, INPUT_SOURCE）, T02 の `src/stemapp/audio.py` と `src/stemapp/separation/pipeline.py`

## 目的
曲をアプリに取り込む入口を作る。ローカルのファイルと URL（yt-dlp）から TRACK と INPUT_SOURCE を作り、同じ曲の二重登録を防ぐ。
分割の起動はここではしない（ジョブ化は T04）。CLI から「取り込み → 分割」を順に呼べれば十分。

## 作るもの

### 1. 取り込みサービス `src/stemapp/ingest/`
- `import_file(session, settings, path, original_name=None) -> ImportResult`
  - T02 の正規化を使って `data/tracks/<track_id>/normalized.wav` を作り、`audio_hash` で既存の TRACK を探す。
  - 既にあれば新しい TRACK を作らず、その TRACK に INPUT_SOURCE を1行足して「既存」と返す（正規化したファイルは捨てる）。
  - 無ければ TRACK（title は タグ → ファイル名 の順で決める。artist と duration_sec も入れる）と INPUT_SOURCE（source_type=file, fetch_status=done）を作る。
  - 元のファイルは移動も削除もしない。
  - タグの読み取りは ffprobe（無ければ空）。ffprobe の呼び出しは差し替えられるようにする。
- T02 の `separate_file` の正規化・TRACK 作成部分と処理が重なる場合は、共通化して `separate_file` がこの取り込みサービスを使うようにする（二重実装にしない）。T02 のテストは壊さないこと。
- `ImportResult`: track_id, is_new（新規か既存か）, 既存なら完了済みの full ジョブがあるか。

### 2. URL 取得 `src/stemapp/ingest/url.py`
- `YtDlpRunner` プロトコルと2つの実装:
  - `ExeYtDlpRunner`: 設定の `ytdlp_path`（`C:\mine\yt-dlp.exe`）を subprocess で呼ぶ。
  - `ModuleYtDlpRunner`: exe が見つからないとき用。Python パッケージ yt-dlp（optional `url`）を `python -m yt_dlp` で呼ぶ。
  - どちらを使うかは起動時に決める（exe があれば exe）。
- 取得方法: 音声だけを最高音質で取得（`-f bestaudio/best`、再エンコードしない）。保存先は `data/cache/downloads/<一時ID>/`。タイトル・アーティスト（uploader）・長さは `--print-json` または `--dump-json` で得る。プレイリスト URL は先頭1曲だけ（`--no-playlist`）。
- 取得後は `import_file` に渡し、INPUT_SOURCE は source_type=url, url, fetch_status=done, fetched_at を入れる。ダウンロードした一時ファイルは取り込み後に消す。
- 失敗したら、TRACK は作らず、INPUT_SOURCE を track_id=NULL・fetch_status=failed・error_code・error_detail（yt-dlp の stderr の最後の数行）で残す。ER で track_id が NULL を許していなければ、その点を報告して判断を仰ぐ（勝手にスキーマを変えない）。
- 理由コードの分類 `classify_error(stderr: str, returncode: int) -> str`（SPEC 8章）:
  unsupported_site, login_required, geo_blocked, private_or_removed, drm, network, needs_update, unknown。
  - yt-dlp の実際のエラーメッセージ（"Unsupported URL", "Sign in to confirm", "Private video", "Video unavailable", "not available in your country", "DRM", "HTTP Error 403", "Unable to download webpage", "nsig extraction failed" など）に基づく規則表を作る。規則はデータ（リスト）で持ち、追加しやすくする。
  - 各コードの日本語メッセージ（ユーザーに見せる文）も持つ。例: needs_update →「yt-dlp が古い可能性があります。更新してから再度お試しください」。
- 更新: `update_ytdlp()` で `yt-dlp.exe -U` を実行し、結果（更新した／最新／失敗）を返す。exe 版のみ対応でよい。

### 3. CLI（`cli.py` に追加）
- `stemapp import <ファイル|URL>`: 取り込んで、track_id・新規か既存か・タイトルを表示する。URL かどうかは `http://` / `https://` で始まるかで判断。
- `stemapp separate` は URL も受け付けるようにする（取り込み → 分割）。既存の曲で分割済みなら T02 と同じく分割しない。
- `stemapp ytdlp-update`: yt-dlp を更新する。

### 4. テスト
- import_file: 新規登録、同じ音の2回目は既存扱いで INPUT_SOURCE が増える、別ファイル名・別形式でも音が同じなら既存扱い、タイトルの決め方（タグあり／なし）。音源はテストの中で numpy で作る。ffmpeg が要るものには `@pytest.mark.ffmpeg`。
- classify_error: 各理由コードに実際の yt-dlp のメッセージ例を最低1つずつ当てる。どれにも当たらなければ unknown。
- URL 取得: Fake の YtDlpRunner（成功時は numpy で作った音声ファイルと JSON を返す、失敗時は stderr と終了コードを返す）で、成功時の登録、失敗時の INPUT_SOURCE（failed・理由コード）、一時ファイルの削除、exe が無いときに Module 版が選ばれること。
- ネットワークに出るテストは作らない（通常テストでも gpu テストでも）。

## 実機での確認（完了条件に含む）
- 誰でも取得してよい短い音源の URL で `stemapp import <URL>` を実行し、TRACK と INPUT_SOURCE ができることを確かめる。URL は次のどちらかにする: YouTube 公式の Creative Commons で公開された短い動画、または Wikimedia Commons の音声ファイル。使った URL を報告する。
- 存在しない動画の URL（例: `https://www.youtube.com/watch?v=xxxxxxxxxxx`）で失敗させ、理由コードが private_or_removed か unknown 以外の妥当なものになることを確かめる。
- `stemapp ytdlp-update` を1回実行する。
- 取り込んだ曲で分割はしなくてよい（時間がかかるため）。

## 注意
- `uv run` が「ファイルが使用中」で失敗する場合、ユーザーの `stemapp serve` が動いている可能性がある。サーバーを止めずに `uv run --no-sync` を使い、報告に書く。

## 完了条件

3. `uv run ruff check` がエラーなし
4. 実機で URL 取得の成功1件と失敗1件が上記どおりに動く
5. ブランチ `task/T03-import` にコミット（main へのマージは監督役）
