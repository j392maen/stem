# T05 再生 UI（PC ブラウザ）

ブランチ: `task/T05-player-ui`（main から作成）
前提資料: `docs/SPEC.md`（1章・4章・7章）, `docs/ER.md`, `docs/PEAKS.md`, `docs/PLAN.md` の「持ち越し事項」, T04 の API（`src/stemapp/api/`）

## 目的
PC のブラウザで、曲の取り込みから分割、stem の組み合わせを再生中に即時に切り替えて聴くところまでを画面で行えるようにする。
iPhone 向けの最適化（選択中の stem だけ読み込む、PWA、ロック画面など）は T06 で行う。ただし画面はスマホの縦画面でも崩れない配置にしておく。

## デザイン（ユーザーの希望）
- 暗い背景の DJ ソフト風。
- 差し色は赤系統で1〜3色（例: 主の差し色に明るい赤、補助に深い赤やローズ）。再生ボタン、選択中の状態、再生位置の線などに使う。差し色を増やしすぎない。
- stem の色（STEM_TYPE.color）は波形とボタンの識別用で、差し色とは別に扱う。T01 の持ち越し事項どおり、似た色（黄色系、オレンジ系）を見分けやすい色に調整し、グループの色も代表 stem と別の色にする。暗い背景の上で見分けやすく、差し色の赤と紛れない色にする（seed の更新で既存 DB にも反映されること）。
- 文字は日本語。フォントは OS 標準（外部フォントを読み込まない）。

## 技術の決まり（SPEC 3章・7章）
- ビルド不要の素の JavaScript（ES modules）＋ Canvas ＋ Web Audio API。npm・外部 CDN は使わない。
- 静的ファイルは `src/stemapp/web/` に置き、FastAPI から `/` で配信する（`/api` と衝突させない）。
- 再生: 全 stem の AudioBuffer を同じ AudioContext の同じ時刻で start する。stem の ON/OFF は GainNode を 0/1 に 15ms 程度のランプで変える（再生を止めない）。シーク時は全 stem を止めて、同じ時刻から同時に start し直す。
- 音声は stream rendition（Opus/WebM）を fetch して decodeAudioData する。配信用データが無いジョブは「配信用データがありません」と表示し、作り直すボタンを出す（下記 API）。
- 波形: peaks（STPK）を読み、概観（曲全体）と拡大（再生位置を中央に固定してスクロール）の2段。選択中の stem を stem 色で重ねて描き、非選択は描かないか暗く描く。表示の幅に応じて samples_per_px の段階を選ぶ。requestAnimationFrame で滑らかに動かす。
- SSE は、終わった状態（done / failed / canceled）を受け取ったら `EventSource.close()` する（T04 持ち越し）。
- `/api/me` が 401 ならログイン画面を出す。

## 作るもの

### 1. 画面
1. **ログイン**（パスコード設定時のみ）
2. **ライブラリ**: 曲の一覧（タイトル、アーティスト、長さ、状態）。ファイルのドラッグ＆ドロップ／選択、URL 入力で取り込み（品質プリセットを選べる。既定は standard）。取り込み・分割中は進捗バーと段階（日本語）を表示し、キャンセルできる。失敗時は理由の日本語メッセージ。曲の削除（確認つき）。
3. **プレイヤー**:
   - 再生／一時停止、シーク（波形のクリック・ドラッグ）、現在時刻／長さ、音量。
   - stem ボタン（STEM_TYPE の display_order 順、stem 色）。押すと即時に ON/OFF。無音（is_silent）の stem は薄く表示。親子関係（vocals と lead/backing）は、親を ON にすると子の状態に関係なく親の音を鳴らす、などの矛盾が起きないように扱う（ルールを決めて報告に書く。例: 子の lead/backing を使うときは親 vocals を鳴らさない）。
   - グループボタン（STEM_GROUP）: 押すとそのグループの stem をまとめて ON/OFF。
   - 組み合わせプリセット（LISTEN_PRESET）: 一覧から選ぶと即時に切り替わる。今の組み合わせを名前を付けて保存、名前の変更、削除、並び替え。
   - 「全部」（元の曲と同じ）と「ソロ」（押した stem だけ）の操作。
   - キューポイント: 今の位置に追加、ラベルと色、クリックでその位置へ移動、削除。ループ: キューに終点を付けるとその区間をくり返す（A-B ループ）。ループの ON/OFF。
   - キーボード操作: スペースで再生／停止、1〜9 で stem の ON/OFF、←→で数秒戻る／進む、L でループ切替。
4. 画面の切り替えは1ページ内（ハッシュ `#/library`, `#/track/<id>`）。

### 2. API の追加・変更
- 組み合わせプリセット: `POST /api/listen-presets`（name, items）、`PUT /api/listen-presets/{id}`（名前・items・sort_order）、`DELETE /api/listen-presets/{id}`。items は stem_type_id か group_id のどちらか一方と gain_db。
- キューポイント: `GET/POST /api/tracks/{id}/cues`、`PUT/DELETE /api/cues/{cue_id}`。
- 配信用データの作り直し: `POST /api/jobs/{id}/postprocess`（done のジョブで stream rendition か peaks が欠けているとき、ワーカーで作る。GPU は使わないが、ワーカーのキューに載せて1件ずつ処理してよい。やり方は判断して報告）。
- CLI の `stemapp separate` も分割後に配信用データを作るようにする（T04 持ち越し）。
- 必要に応じて、画面に必要な情報を既存 API に足してよい（二重の API を作らない）。

### 3. テスト
- API: 追加したエンドポイントの正常系・異常系（404、検証エラー、LISTEN_PRESET_ITEM の「どちらか一方」）。
- 静的ファイル配信: `/` で index.html、`/api/*` は従来どおり。
- ブラウザのテスト（`@pytest.mark.browser`、通常実行では除外し `-m browser` で実行）:
  - Python の Playwright を dev 依存に追加し、**ブラウザ本体はダウンロードせず** PC にある Microsoft Edge（`channel="msedge"`）を使う。`playwright install` は実行しない。
  - テスト用に Fake の分離器で動くサーバー（一時データフォルダ）を起動し、次を確かめる: ライブラリ表示 → 短い合成音を取り込み・分割（Fake）→ プレイヤーを開く → 再生が始まる（AudioContext の currentTime が進む）→ stem ボタンで GainNode の値が変わる（テスト用に状態を読める仕組みを `window.__stemapp` などで用意してよい）→ プリセット保存 → キュー追加 → ループ。
  - 画面のスクリーンショットを PC 幅（1440×900）とスマホ幅（390×844）で撮り、`data/cache/screens/` に保存する（コミットしない）。報告にパスを書く。
- JavaScript の純粋な処理（peaks の読み取り、段階の選び方、親子のルール、時刻計算）は、ブラウザのテストの中で評価して確かめてよい。

## 実機での確認（完了条件に含む）
- `uv run stemapp serve`（別ポートでよい）を起動し、実モデル（fast）で 1〜2 分の合成音を画面から取り込み・分割し、再生と stem 切り替えができるところまで Playwright（Edge）で操作してスクリーンショットを撮る。
- 確認用に作った曲は最後に削除し、プロセスを止める。

## 注意
- ユーザーの `stemapp serve`（ポート 8000）が動いていたら止めず、別ポートを使う。`uv run` が「ファイルが使用中」で失敗したら `--no-sync` を使い、報告に書く。
- 足す依存は Playwright（dev のみ）だけにし、他に必要なら報告で理由を書く。
