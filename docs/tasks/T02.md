# T02 分離パイプライン（CLI）

ブランチ: `task/T02-separation`（main から作成）
前提資料: `docs/SPEC.md`（特に4章・5章）, `docs/ER.md`, T01 で作った `src/stemapp/`（models.py, seed.py, config.py）

## 目的
1曲を品質プリセット（fast / standard / best）どおりに stem に分け、ファイルと DB に保存するところまでを CLI で動かす。
ジョブの管理・API・Opus 変換・波形は T04、URL 取得と取り込みの重複処理は T03 で行うので、ここでは作らない。

## 作るもの

### 1. 音声の正規化 `src/stemapp/audio.py`
- ffmpeg で入力（mp3/m4a/flac/wav など）を 44.1kHz・ステレオ・32bit float の WAV に変換する。モノラルは2チャンネルに複製する。
- `audio_hash` は正規化後の PCM サンプル列の SHA-256（ファイルのヘッダは含めない）。
- 読み書きは soundfile、配列は numpy（形は `(samples, 2)`、float32）。
- ffmpeg を呼ぶ部分は差し替えられるようにし、ffmpeg が要るテストには `@pytest.mark.ffmpeg` を付ける（無ければ skip）。

### 2. 分離器の抽象 `src/stemapp/separation/`
- `Separator` プロトコル: 1つのモデルを入力 WAV に適用し、`{出力名: numpy 配列}` を返す。引数はモデルのファイル名、options（overlap、tta、チャンク長など）、デバイス（cuda/cpu）。
- `AudioSeparatorBackend`: python-audio-separator を使う実装。
  - モデルの置き場は設定の `models_dir`。無ければ audio-separator が自動でダウンロードする（そのままでよい）。
  - モデルは1つずつロードし、使い終わったら解放する（`del` と `torch.cuda.empty_cache()`）。
  - fp16（autocast）を使う。
  - audio-separator の出力ファイル名（"(Vocals)" など）を stem の名前に対応づける表を持つ。karaoke モデルは "(Vocals)"=lead、"(Instrumental)"=それ以外。
  - `audio-separator` を import するのはこのモジュールの中だけにし、GPU 依存が無い環境でも他のコードとテストが動くようにする。
- `FakeSeparator`: テスト用。GPU もモデルも使わず、決まった計算（例: 入力に固定の係数を掛けて振り分ける）で出力を作る。わざと出力の合計が入力と少しずれるようにし、残差補正が効くことをテストできるようにする。指定した回数だけ OOM を起こす機能を持たせる。

### 3. パイプライン `src/stemapp/separation/pipeline.py`
- DB の SEPARATION_PRESET と PRESET_STEP を読んで手順を組み立てる（手順をコードに直書きしない）。
- 流れ（SPEC 5章）:
  1. multistem（BS-Roformer-SW）で vocals, drums, bass, guitar, piano, other を得る。
  2. role=vocals のステップの出力と SW の vocals を `ensemble_weight` で重み付き平均し、vocals とする。
  3. vocals に karaoke モデルをかけ lead を得る（karaoke が複数あれば重み付き平均）。
  4. backing = vocals − lead。
  5. other += mixture − (vocals + drums + bass + guitar + piano + other)。これで上位 stem の合計が元の曲と一致する。
- STEM の木構造: 上位は vocals, drums, bass, guitar, piano, other。lead_vocal と backing_vocal は vocals の子で、backing_vocal が `is_residual=true`。
- 各 stem の `rms_db` を計算し、-60 dBFS 未満なら `is_silent=true`。
- 保存:
  - ファイル: `data/stems/<job_id>/<stem_type の code>.flac`（24bit）。正規化した音源は `data/tracks/<track_id>/normalized.wav`。
  - DB: TRACK、SEPARATION_JOB（job_kind=full）、STEM、STEM_RENDITION（purpose=master, codec=flac）を登録する。
  - 同じ `audio_hash` の TRACK に完了済みの full ジョブがあれば、分割せずにそれを知らせて終わる（`--force` で再分割）。
  - クリップ（絶対値 1 を超えるサンプル）が起きた stem があれば件数をログに出す。
- 進捗: `progress(0〜1)` と `stage`（日本語の短い説明）を JOB に書き、コールバックでも受け取れるようにする（T04 で使う）。
- 失敗時は JOB を failed にし、`error_message` を日本語で残す。

### 4. OOM への対応
- GPU のメモリ不足（`torch.cuda.OutOfMemoryError`、または "out of memory" を含む RuntimeError）が起きたら、チャンク（segment）を小さくして同じステップをやり直す。
- 決めた回数だけ縮めても失敗したら CPU で実行する。どの段階で何を変えたかをログに残す。
- テストは FakeSeparator の OOM 機能で確認する。

### 5. CLI（`src/stemapp/cli.py` に追加）
- `stemapp separate <ファイル> [--preset fast|standard|best] [--force] [--cpu]`: 既定のプリセットは DB の is_default。終わったら stem ごとの表（名前、rms_db、無音か、ファイルパス）と所要時間を日本語で出す。
- `stemapp bench <ファイル> [--presets fast,standard]`: プリセットごとに、全体の時間、ステップごとの時間、GPU メモリの最大使用量（`torch.cuda.max_memory_allocated`）を測って表で出し、`data/cache/bench/<日時>.json` に保存する。bench の結果は DB に登録しない（一時フォルダで分割して捨てる）。

### 6. テスト
- 正規化: 44.1kHz・ステレオになる、モノラルが複製される、同じ音なら hash が同じ（`@pytest.mark.ffmpeg`）。
- パイプライン（FakeSeparator）:
  - fast / standard / best のそれぞれで、上位 stem の合計が mixture に一致（float で誤差 1e-5 以内）、lead + backing が vocals に一致。
  - ensemble の重み付き平均が正しい。
  - DB に TRACK / JOB / STEM / RENDITION が正しく入り、木構造と is_residual が正しい。FLAC を読み戻して合計が一致（24bit の量子化誤差の範囲）。
  - 無音の stem が is_silent になる。
  - 同じ曲の2回目は分割しない、`--force` なら分割する。
  - OOM → チャンク縮小 → CPU の順に切り替わる。
  - 分離器が例外を出したら JOB が failed になり、メッセージが残る。
- テスト用の音源はテストの中で numpy で作る（正弦波など）。音源ファイルをコミットしない。
- GPU テスト（`@pytest.mark.gpu`）: AudioSeparatorBackend で短い音（10秒ほどの合成音）を fast で分割し、6+2 の stem ができて合計が一致すること。

## 実機での確認（完了条件に含む）
- まず `audio-separator --list_models` などで、SPEC 5章のモデル名が 0.47.0 で使えるか確かめる。使えないものがあれば、勝手に別モデルに替えず、報告に書く（fast / standard に必要なものが使えない場合はそこで止めて報告）。
- モデルのダウンロードは fast と standard に必要な分まで。best 用の追加モデルはダウンロードしなくてよい（best は Fake のテストだけで可）。ダウンロードした合計サイズを報告する。
- 4分程度の音源で `stemapp bench --presets fast,standard` を実行する。手元に曲が無ければ、ffmpeg か numpy で 4分の合成音（複数の楽器風の音を重ねたもの）を `data/cache/` に作って使ってよい（音質ではなく時間と VRAM を測る目的）。
- 同じ音源で `stemapp separate --preset standard` を実行し、DB 登録と FLAC ができることを確かめる。
