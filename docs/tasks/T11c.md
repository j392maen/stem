# T11c PC で速度がすぐ変わる方式（ブラウザ内の伸縮）

ブランチ: `task/T11c-instant-stretch`（main から作成）
前提資料: `docs/research/R01-bpm-tempo-quality.md` C-2 (a), `docs/tasks/T11.md`, T11 の `web/js/engine.js`・`tempo.js`, T07 の親子 stem

## 目的（ユーザーの選択）
「ピッチを保つ」速度変更を、PC ではサーバーでの作成を待たずに、スライダーを動かすとすぐ変わるようにする（ユーザーが「PC は即時」を選択済み）。iPhone では今の方式（サーバーで作る）を使う。

## 決まり
- ブラウザ内の伸縮には **signalsmith-stretch**（MIT）を使う。npm・CDN は使えないので、配布されている JS/WASM のファイルを `src/stemapp/web/vendor/signalsmith-stretch/` に同梱する（取得元の URL・版・ライセンス文をそのフォルダの README とライセンスファイルに残す）。他のライブラリが良いと判断した場合は、理由を報告して止まる。
- AudioWorklet で動かす。全 stem の同期（同じ時刻・同じ倍率）、stem の即時 ON/OFF（GainNode または worklet 内の音量）、シーク、ループ、拍の線・キュー・BPM 表示（曲時刻で持つ）を今までどおり保つ。
- 処理の形は CPU 負荷を測って決める。候補: (a) stem ごとに伸縮器を持つ（素直だが stem 数倍の負荷）、(b) stem に音量をかけて混ぜてから1つの伸縮器にかける（負荷は1つ分。stem の切り替えは混ぜる前に効く）。8 stem・4 分の曲で、この PC（Core i7-14650HX）の Edge で音が途切れないことを確かめ、CPU 使用率を報告する。
- 方式の選択肢を「ピッチも変わる（すぐ）」「ピッチを保つ・すぐ（PC）」「ピッチを保つ・高音質（サーバーで作る）」の3つにする。既定は、PC（ポインタが細かい・画面が広い）では「すぐ（PC）」、スマホではサーバー方式。ユーザーが選んだものを曲ごとに覚える（T11 と同じ）。
- 音質: 伸縮の品質を T11 のサーバー方式（rubberband R2）と聴き比べられるよう、同じ倍率で切り替えられるようにする。時刻のずれ（曲時刻との差）を T11 と同じ方法で測り、±5ms 以内に補正する（遅延の補正が必要なら入れる）。
- 速度を変えても再生を止めない。倍率の変化は滑らかに（スライダーを動かしている間も音が途切れない）。

## テスト
- 位置計算の純粋関数（T11 のものを再利用、即時方式でも曲時刻が合うこと）。
- ブラウザテスト（Edge）: 即時方式で速度を変えても再生が止まらない、stem の ON/OFF が効く、シーク・ループ・倍率の変更後に曲時刻が合う（AudioWorklet の出力を OfflineAudioContext かタップで調べられる範囲で）、方式の切り替え、スマホ幅では既定がサーバー方式。スクリーンショット（PC・スマホ幅）。
- 伸縮後の時刻のずれの計測（自動テストにできる範囲で）。
