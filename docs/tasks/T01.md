# T01 基盤づくり

ブランチ: `task/T01-foundation`（main から作成）
前提資料: `docs/SPEC.md`, `docs/ER.md`, `docs/PLAN.md`

## 目的
以降のタスクが乗る土台を作る。分離処理・UI はまだ作らない。

## 作るもの

### 1. プロジェクト骨格
- `pyproject.toml`（uv 管理、Python 3.12、パッケージ名 `stemapp`、`src/` レイアウト、コンソールスクリプト `stemapp`）
  - 依存: fastapi, uvicorn[standard], sqlalchemy>=2, pydantic-settings, numpy, soundfile, typer
  - optional `url`: yt-dlp
  - dev グループ: pytest, httpx, ruff
  - GPU 関連（torch の CUDA 版、audio-separator[gpu]）は **ロックファイルに含めない**。Windows では setup スクリプトが `uv pip install` で後入れする（理由: CUDA 版 torch の配布元はクラウド環境から取得できず、ロック解決が失敗するため）。以後の起動は `uv run --no-sync` 等で後入れ分を消さないこと。
- `.gitignore`、ruff 設定（line-length 100、主要ルール有効）、`README.md`（日本語）

### 2. 設定 `src/stemapp/config.py`
- pydantic-settings。環境変数プレフィックス `STEMAPP_`。
- data_dir（既定: Windows は `%USERPROFILE%\stemapp-data`、それ以外は `~/stemapp-data`）、host=127.0.0.1、port=8000、passcode（任意）、db_path（data_dir/stemapp.db）、各種サブフォルダ（tracks, stems, cache, models）。
- ディレクトリは初回アクセス時に作成。

### 3. DB `src/stemapp/db.py`, `src/stemapp/models.py`
- SQLAlchemy 2.0 の宣言的マッピングで docs/ER.md の全20実体を定義。
- SQLite の外部キーを有効化（PRAGMA foreign_keys=ON）。
- LISTEN_PRESET_ITEM の「stem_type_id と group_id のどちらか一方」を CHECK 制約で保証。
- `init_db()` でテーブル作成。

### 4. 初期データ `src/stemapp/seed.py`（何度実行しても同じ結果になること）
- STEM_TYPE: SPEC 4章の木構造。tier は、分割時に必ず作るもの（vocals, lead_vocal, backing_vocal, drums, bass, guitar, piano, other）を `base`、それ以外を `detail`。lead_vocal/backing_vocal/male/female/breath の親は vocals。日本語表示名と、互いに見分けやすい色を付ける。精度の低いもの（synth, woodwind, percussion, tambourine, hihat, 他 SDR 5 未満相当）は experimental=true。
- MODEL: SPEC 5章に列挙した audio-separator のモデル（ファイル名、出力 stem、license は分かる範囲、不明は "unknown"）。
- SEPARATION_PRESET + PRESET_STEP: fast / standard(既定) / best を SPEC 5章どおりに。
- STEM_GROUP: vocals_all, chords, rhythm, accompaniment（SPEC 4章）。
- LISTEN_PRESET: 「ベース＋コード」「ドラム＋ボーカル＋コード」「カラオケ（伴奏）」「サブボーカルのみ」。

### 5. CLI `src/stemapp/cli.py`（typer）
- `stemapp init-db`: DB 作成＋初期データ投入。
- `stemapp doctor`: 環境診断を日本語で表形式表示。項目ごとに OK / 注意 / NG と対処のヒント。
  - Python バージョン、データフォルダ書き込み、DB 初期化 → 失敗は NG
  - ffmpeg（バージョン）、torch と CUDA（GPU 名・VRAM）、audio-separator、yt-dlp、deno → 無ければ「注意」
  - NG が1つでもあれば終了コード 1。
  - 各診断は関数単位に分け、テストで差し替えられるようにする（subprocess や import を直接叩かない形）。
- `stemapp serve`: FastAPI を config の host/port で起動。

### 6. API `src/stemapp/app.py`
- `create_app()` ファクトリ。`GET /api/health` → `{"status": "ok", "version": "<パッケージ版>"}`。
- 起動時に init_db と seed を実行。

### 7. Windows 用スクリプト `scripts/windows/`
- `setup.ps1`: uv が無ければ公式手順で導入 → winget で ffmpeg（Gyan.FFmpeg）と Deno（DenoLand.Deno）→ `uv sync --extra url` → CUDA 版 torch（cu128 の公式 index）と `audio-separator[gpu]` を `uv pip install` → `stemapp init-db` → `stemapp doctor`。各段階で日本語メッセージ。既に入っている物はスキップ。
- `start.bat`: サーバー起動（ダブルクリックで動く）。
- この環境では実行確認できないので、構文が妥当であることをレビューで重点確認する。

### 8. テスト `tests/`
- 設定の既定値と環境変数上書き
- 全テーブル作成、外部キー有効、CHECK 制約違反が弾かれる
- seed の冪等性（2回実行で件数不変）、木構造の整合（親が存在、循環なし）、グループ構成
- doctor（診断関数を差し替えて OK/注意/NG と終了コードを確認）
- `/api/health`（TestClient）
- テストは一時ディレクトリの DB を使い、実ユーザーのフォルダを汚さない。

## 完了条件
1. `uv run pytest -q` が全件成功（GPU・ffmpeg なしの Linux で）
2. `uv run ruff check` がエラーなし
3. `uv run stemapp init-db` と `uv run stemapp doctor` がこの環境で動く（GPU 無しは「注意」になり NG にならない）
4. `uv run stemapp serve` 起動後 `curl http://127.0.0.1:8000/api/health` が ok
5. 変更をブランチ `task/T01-foundation` にコミット（main にはマージしない）
