## 作るもの

### 1. プロジェクト骨格
- `pyproject.toml`（uv 管理、Python 3.12、パッケージ名 `stemapp`、`src/` レイアウト、コンソールスクリプト `stemapp`）
  - 依存: fastapi, uvicorn[standard], sqlalchemy>=2, pydantic-settings, numpy, soundfile, typer
  - optional `gpu`: audio-separator[gpu]、torch（CUDA 12.8 版。`[[tool.uv.index]]` に `https://download.pytorch.org/whl/cu128` を explicit で登録し、`[tool.uv.sources]` で Windows のときだけその index を使う）
  - optional `url`: yt-dlp（yt-dlp.exe が無いときの予備）
  - dev グループ: pytest, httpx, ruff
- `uv.lock` をコミットする。
- `.gitignore`（data/, .env, .venv, __pycache__ 等）、`.env.example`（`STEMAPP_DATA_DIR=C:\mine\stem\data`、`STEMAPP_YTDLP_PATH=C:\mine\yt-dlp.exe`）、ruff 設定（line-length 100）、`README.md`（日本語。セットアップ、起動、テストの手順）

### 2. 設定 `src/stemapp/config.py`
- pydantic-settings。環境変数プレフィックス `STEMAPP_`、`.env` を読む。
- data_dir（既定はリポジトリ直下の `data`）、host=127.0.0.1、port=8000、passcode（任意）、ytdlp_path、db_path（data_dir/stemapp.db）、サブフォルダ（tracks, stems, cache, models）。
- ディレクトリは初回アクセス時に作成。

### 3. DB `src/stemapp/db.py`, `src/stemapp/models.py`
- SQLAlchemy 2.0 の宣言的マッピングで docs/ER.md の全20実体を定義。
- SQLite の外部キーを有効化（PRAGMA foreign_keys=ON）。
- LISTEN_PRESET_ITEM の「stem_type_id と group_id のどちらか一方」を CHECK 制約で保証。
- `init_db()` でテーブル作成。

### 4. 初期データ `src/stemapp/seed.py`（何度実行しても同じ結果）
- STEM_TYPE: SPEC 4章の木構造。分割時に必ず作るもの（vocals, lead_vocal, backing_vocal, drums, bass, guitar, piano, other）は tier=`base`、それ以外は `detail`。lead_vocal/backing_vocal/male/female/breath の親は vocals。日本語表示名と、見分けやすい色。精度が低いもの（synth, woodwind, percussion, tambourine, hihat など）は experimental=true。
- MODEL: SPEC 5章の audio-separator モデル（ファイル名、出力 stem、license は分かる範囲、不明は "unknown"）。
- SEPARATION_PRESET + PRESET_STEP: fast / standard(既定) / best を SPEC 5章どおりに。
- STEM_GROUP: vocals_all, chords, rhythm, accompaniment。
- LISTEN_PRESET: 「ベース＋コード」「ドラム＋ボーカル＋コード」「カラオケ（伴奏）」「サブボーカルのみ」。

### 5. CLI `src/stemapp/cli.py`（typer）
- `stemapp init-db`: DB 作成＋初期データ投入。
- `stemapp doctor`: 環境診断を日本語の表で表示。項目ごとに OK / 注意 / NG と対処のヒント。
  - Python、データフォルダ書き込み、DB → 失敗は NG
  - ffmpeg、torch と CUDA（GPU 名・VRAM・CUDA 版）、audio-separator、yt-dlp（exe のパスとバージョン）、deno → 無ければ注意
  - NG が1つでもあれば終了コード 1。
  - 各診断は関数単位に分け、テストで差し替えられるようにする。
- `stemapp serve`: FastAPI を設定の host/port で起動。

### 6. API `src/stemapp/app.py`
- `create_app()` ファクトリ。`GET /api/health` → `{"status": "ok", "version": "<版>"}`。
- 起動時に init_db と seed。

### 7. Windows 用スクリプト `scripts/`
- `setup.ps1`: 事前確認と同じ道具の確認・導入 → `uv sync --extra gpu --extra url` → `.env` が無ければ `.env.example` から作成 → `stemapp init-db` → `stemapp doctor`。日本語メッセージ。既にあるものはスキップ。
- `start.bat`: サーバー起動（ダブルクリックで動く）。

### 8. テスト `tests/`
- 設定の既定値と環境変数上書き
- 全テーブル作成、外部キー有効、CHECK 制約違反が弾かれる
- seed の冪等性、木構造の整合（親が存在、循環なし）、グループ構成
- doctor（診断関数を差し替えて OK/注意/NG と終了コードを確認）
- `/api/health`
- `tests/test_gpu.py`（`@pytest.mark.gpu`）: torch.cuda.is_available() と簡単な GPU 演算
- テストは一時ディレクトリの DB を使い、`C:\mine\stem\data` を汚さない。

## 完了条件
1. `uv run pytest -q`（gpu 以外）が全件成功
2. `uv run pytest -q -m gpu` が成功（RTX 4060 を認識）
3. `uv run ruff check` がエラーなし
4. `.\scripts\setup.ps1` を再実行しても壊れない。`uv run stemapp doctor` で GPU・ffmpeg・yt-dlp.exe・deno が OK
5. `uv run stemapp serve` 起動後、`http://127.0.0.1:8000/api/health` が ok
6. ブランチ `task/T01-foundation` にコミット（main へのマージは監督役）
