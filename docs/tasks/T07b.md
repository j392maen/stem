# T07b Mega 53 を 8GB で試す（実験）

ブランチ: `task/T07b-mega53`（main から作成）
前提資料: `docs/research/R01-bpm-tempo-quality.md` D-3, `docs/tasks/T07.md`, T07 の `src/stemapp/separation/refine.py`

## 目的（ユーザーが「HPSS と Mega 53 も試す」を選択済み）
「その他」に入りすぎる問題（パッド＝ストリングス／シンセ等と、オーケストラヒットが一緒になる）への対策として、MVSep の Mega 53 stems（ZFTurbo の MSST 形式の BS-Roformer）が、この PC（RTX 4060 Laptop 8GB）で動くか、どの程度分けられるかを確かめる。動けば T07 の「もっと分ける」の方法の1つとして使えるようにする。

## 進め方
1. **調査（先に報告して判断を仰ぐ）**: 次を一次情報で調べ、`docs/research/R02-mega53.md` にまとめる。
   - 重み・設定ファイルの入手先、サイズ、ライセンス（不明なら不明と書く）。
   - 推論に必要なコード（ZFTurbo の Music-Source-Separation-Training の該当部分）と、そのライセンス。必要な Python パッケージのうち、今の `.venv` に無いもの。
   - 53 stem の名前の一覧と、stemapp の STEM_TYPE（other の子: strings, synth, keys, organ, brass, woodwind, saxophone, percussion 等）との対応。
   - 公表されている必要 VRAM と、8GB で動かす工夫（チャンク・fp16・バッチ 1 等）。
   - **新しい Python パッケージが必要な場合や、重みが 2GB を超える場合は、調査結果を報告してそこで止まる**（監督役がユーザーに確認する）。必要なものがすべて今の `.venv` にあり、重みが 2GB 以下で、ライセンス上も個人利用に問題がなければ、2 に進んでよい。
2. **試用**: 推論コードは必要な部分だけをリポジトリに取り込む（`src/stemapp/separation/msst/` など。元のライセンス文と取得元・版を残す）。重みは `data/models`（共有の置き場）に置く。
   - ユーザーの曲のコピー（一時データフォルダ）で、other stem（親）を Mega 53 にかけ、処理時間・GPU メモリ・各出力の RMS を報告する。OOM になればチャンクを縮める等で再試行し、どこまで縮めれば動くかを報告。
   - 合計が親に一致しないモデルなので（R01 D-3）、「残り＝親 − 名前の付いた子の合計」で必ず合計を合わせる（T07 の規則どおり）。
3. **組み込み**（2 で実用になると判断できた場合だけ）: T07 の refine の方法として追加する（other に「もっと分ける（Mega 53）」）。出力のうち実質的に無音のもの（例: −60dB 未満）は子として作らず残りに入れる。STEM_TYPE が足りなければ seed に追加。画面は T07 のままで使えること。

## テスト
- 組み込む場合: Fake で合計一致・無音の子を作らないこと・木構造、GPU テスト（短い合成音）、ブラウザテスト（Fake）。
- 組み込まない場合: 調査と試用の結果の報告だけでよい（コードは入れない）。

## 注意
- git worktree で行う。実行は `C:\mine\stem\.venv\Scripts\python.exe` と PYTHONPATH。GPU は STEMAPP_MODEL_DIR=C:\mine\stem\data\models。bash で cygpath を使わない。
- 実データ（`C:\mine\stem\data`）は読み取りのみ（モデルの置き場 `data/models` への追加は可）。ユーザーのサーバー（8000）には触らない。
- `uv sync` や `pip install` で依存を足さない（足す必要があれば 1 で止まって報告）。
