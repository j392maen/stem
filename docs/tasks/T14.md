# T14 仕上げ（レビューで後回しにした改善のまとめ）

ブランチ: `task/T14-polish`（main から作成）
前提資料: `docs/PLAN.md` の持ち越し事項, `docs/ER.md`, 各タスクの指示書

## 目的
これまでのレビューで「後で」とした改善を、まとめて片付ける。画面の新機能は最小限にし、主にサーバー側・後始末・テストの安定化を行う。

## 作るもの
1. **番号の使い回しを防ぐ（AUTOINCREMENT）**
   - SQLite は、最大の番号の行を消すと次にその番号を使い直す。job_id・export_id などはフォルダ名（旧 `stems/<job_id>`、`cache/tempo/<job_id>`、`exports/<export_id>`、`cache/tmp/job-<id>`）にも使われているので、取り違えの恐れがある。
   - 対象の表（少なくとも TRACK、SEPARATION_JOB、STEM、EXPORT、TEMPO_RENDER、BEAT_EDIT、INPUT_SOURCE）を AUTOINCREMENT にする。新しく作る DB は最初から、既存の DB は移行で作り直す（SQLite は ALTER で付けられないので、表を作り直してデータを移す。外部キーと索引を保つ）。
   - 移行の前に DB のバックアップを `data/backup/stemapp-<日時>.db` に作る。移行は `init_db` で自動に行ってよいが、失敗したら元に戻し、起動を止めて日本語で案内する。何度実行しても同じ結果になること。
   - 実データのコピーで移行を試し、行数・外部キー・アプリの起動を確かめて報告する（実データ本体には行わない。本番の移行は、次にユーザーがサーバーを起動したときに自動で行われることになるので、その旨を報告に書く）。
2. **ワーカーの状態**
   - `/api/health` にワーカーの状態（動いているか、最後に生きていた時刻、実行中のジョブ）を加える。
   - serve はワーカーが落ちたら起動し直す（短い間に何度も落ちるときは間隔を空け、画面に「分割の処理が止まっています」を出す）。
3. **速度変更の作成を分割と並行に**（T11 レビューより）
   - 伸縮（rubberband、CPU のみ）を、分割（GPU）とは別のスレッドまたはプロセスで動かし、分割中でも待たされないようにする。同時に動かす数は1つ。キャンセル・起動時の片付け・キャッシュの上限は今のまま効くこと。
4. **書き出しの仕上げ**（T08 レビューより）
   - cleanup を Lock で1本ずつにし、同時実行の StaleDataError を無くす。
   - mix の合計を float32 で行いメモリを半分にする（24bit 相当の精度は保つ）。
   - 完了後は「作成する」ボタンを控えめ（枠線だけ）にし、「ダウンロード」を主にする。
   - そのジョブの書き出しの一覧と再ダウンロード（期限内のもの）を書き出しメニューに出す（`GET /api/jobs/{id}/exports`）。
   - MP3 に曲名・アーティスト・stem 名（または組み合わせ名）のタグを付ける。
5. **端末の診断の仕上げ**（T06a レビューより）
   - `data/diag` の件数の上限（200 件。古い順に消す）。
   - `test_browser_diag.py::test_diag_page_desktop` が全体実行でときどき失敗する（保存の直後に読み出す競合、保存名が秒単位で同じ秒だと `-2.json` になり名前順で古い方が先頭になる）。保存名・並べ方・テストの待ち方を直して安定させる。
   - Service Worker が /api/ と音声をキャッシュしないことを、ブラウザテストで Cache Storage の中身を読んで確かめる。
   - Host が無いとき（400）と WebSocket（1008 で閉じる）のテスト。
   - Host のポート判定を `isascii() and isdigit()` に。
   - manifest の icon の purpose を any と maskable に分けて書く。
6. **拍の解析の警告**（T12 より）: `POST /api/tracks/{id}/beats` に job_id を任意で渡せるようにし、画面は表示中のジョブを渡す（警告が表示中のジョブに付くように）。
7. **ログの見やすさ**: onnxruntime-gpu（CUDA 13 版）と torch（cu128）の不一致で出る警告・DLL 読み込み失敗のメッセージを、実害が無いことを確かめた上で抑える（または1行の注意にまとめる）。抑え方を報告する。
8. httpx の非推奨警告は、テスト用クライアントの差し替えで消せるなら消す（依存は足さない）。無理なら据え置き、理由を報告。

## テスト
- 各項目に対応するテスト。AUTOINCREMENT の移行（古い形の DB → 新しい形、データ・外部キー・索引が保たれる、2回目は何もしない、失敗時に元に戻る、最大の番号を消しても次は新しい番号）。
- ブラウザテストを全体で3回続けて実行し、毎回すべて通ることを確かめる（不安定なテストが残っていないこと）。
