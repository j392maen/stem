# T13 stem の保存フォルダ名を元のファイル名にする

ブランチ: `task/T13-folder-names`（T10・T12 をマージした後の main から作成）
前提資料: `docs/ER.md`, T02〜T05 の保存処理（`separation/pipeline.py`, `delivery.py`, `library.py`）, T05b の「保存フォルダを開く」, T12 の「同じ曲の複数ジョブ」

## 目的（ユーザーの要望）
stem を保存するフォルダの名前を、今の `data/stems/<job_id>/` から、**元のファイル名**にする。フォルダ名に使えない文字は、その文字を飛ばす（取り除く）。

## 決まり
- 元のファイル名: 取り込んだときの INPUT_SOURCE.original_name（拡張子を除く）。URL から取り込んだ曲は、そのときのタイトル（今も original_name に入っている）。同じ曲に複数の INPUT_SOURCE があるときは、最初に成功したもの。
- フォルダ構成: `data/stems/<元のファイル名>/<分け方>/`
  - `<分け方>` はプリセットの code（例 `standard`, `fast`, `exp_combo`）。同じ曲の複数ジョブ（T12）を分けるため。同じプリセットの再分割（force）は `standard (2)` のように番号を付ける。
  - 配信用データは今どおりその中の `stream/` に置く。master の FLAC はフォルダの直下（`vocals.flac` など）。
- 使えない文字の扱い（Windows の規則）:
  - `\ / : * ? " < > |` と制御文字（0x00〜0x1F）は飛ばす（取り除く）。
  - 末尾のピリオドと空白は取り除く。前後の空白も取り除く。
  - 予約名（CON, PRN, AUX, NUL, COM1〜9, LPT1〜9。拡張子付きも含む、大文字小文字を区別しない）になった場合は、末尾に `_` を付ける。
  - 取り除いた結果が空なら `track_<track_id>`。
  - 長すぎる名前は 100 文字（Python の文字数）で切る（パス全体の長さの制限を避けるため）。
  - 日本語などの文字はそのまま使う。
- 別の曲が同じフォルダ名になる場合（元のファイル名が同じで音が違う）は、後から来た曲に ` (2)`, ` (3)` … を付ける。
- 名前はフォルダを作るときに一度決め、DB（STEM_RENDITION.file_path など）には今どおりデータフォルダからの相対パスで保存する。後で INPUT_SOURCE が増えてもフォルダ名は変えない。
- 一時フォルダ（`cache/tmp/job-<id>`）やジョブの管理は今のまま（job_id を使う）。

## 既存データの移行
- 既存の `data/stems/<job_id>/` を新しい名前のフォルダへ移し、DB のパス（master・stream の rendition、WAVEFORM の peaks_path など、stems フォルダを指すものすべて）を書き換える。
- 移行は `stemapp migrate-folders`（`--dry-run` で予定だけ表示）として作り、`init_db` では自動で行わない（ファイルを大きく動かすため、ユーザーが実行する）。移行中に失敗したら、そのジョブの分は元に戻し、他のジョブは続ける。何度実行しても同じ結果になる。
- 移行の前後で、ファイル数と合計サイズが同じことを確かめて表示する。

## テスト
- 名前の整形（使えない文字、末尾のピリオドと空白、予約名、空、長さ、日本語）。
- 新しい分割で新しいフォルダ構成になること。複数ジョブ、同じプリセットの再分割、別の曲の同名。
- 曲の削除・ジョブの削除でフォルダが消えること（空になった曲のフォルダも消す）。
- 「保存フォルダを開く」が新しいフォルダを開くこと。
- 移行（dry-run、実行、2回目は何もしない、途中失敗の巻き戻し）。

## 実機での確認
- 実データで `stemapp migrate-folders --dry-run` の結果を報告し、監督役の確認の後で実行する（報告の時点では実行しない。監督役がユーザーの了承を得てから実行を指示する）。
- 一時データフォルダで、日本語・使えない文字を含むファイル名の曲を取り込み・分割し、フォルダ名を確かめる。
