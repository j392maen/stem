# T06a iPhone・外出先の準備（Tailscale、安全策、PWA、端末の診断）

ブランチ: `task/T06a-remote-setup`（main から作成）
前提資料: `docs/SPEC.md` 2章・7章・8章, `docs/PLAN.md` の持ち越し事項（T05b レビュー: Host の許可リスト等）, T04 の認証, T05 の画面

## 目的
iPhone（外出先）から Tailscale 経由で安全にアプリを開けるようにし、iPhone のブラウザで何が使えるか（音声の形式など）を実機で調べる仕組みを作る。再生エンジンの iPhone 向けの変更（選んだ stem だけ読み込む等）は T06b で、ここで集めた診断結果をもとに行う。

## 環境（監督役が確認済み）
- この PC の Tailscale の名前: `unagi.tail8b25a2.ts.net`（MagicDNS 有効、HTTPS 証明書も使える状態）。iPhone（`iphone-13`）も同じ tailnet に参加済み。Tailscale 1.102.4。`tailscale` コマンドは `C:\Program Files\Tailscale\tailscale.exe`。
- 公開は tailnet の中だけ（`tailscale serve`）。インターネット全体に出す Funnel は使わない。

## 作るもの
1. **Tailscale Serve の手順とスクリプト**
   - `scripts/tailscale-serve.ps1`: `tailscale serve --bg --https=443 http://127.0.0.1:<port>` 相当で公開する／状態を表示する／止める（引数で切り替え）。日本語メッセージ。Funnel は使わないことを確認して表示。
   - README に、iPhone からの開き方（`https://unagi.tail8b25a2.ts.net/`）、ホーム画面への追加、パスコードの設定を勧めること、TCP 転送（`tailscale serve --tcp`）や SSH のポート転送では使わないこと（「保存フォルダを開く」の判定のため）を書く。
   - 実際に serve を有効にして、PC から `https://unagi.tail8b25a2.ts.net/api/health` に届くことを確かめる（確かめた後は止めてよい。止めたかどうかを報告）。
2. **安全策（T05b レビューの持ち越し）**
   - Host ヘッダーの許可リスト（Starlette の TrustedHostMiddleware 等）: `127.0.0.1`, `localhost`, `[::1]`, 設定 `STEMAPP_ALLOWED_HOSTS`（既定に `unagi.tail8b25a2.ts.net` は入れず、`.env.example` に例として書く。setup.ps1 か doctor で tailscale の名前を自動で見つけて案内できればなおよい）。許可されない Host は 400。DNS リバインディング対策。
   - 「保存フォルダを開く」の explorer を完全パス（`%SystemRoot%\explorer.exe`）で起動。中継ヘッダーの判定に `x-forwarded-proto`, `x-real-ip`, `via` を追加。
   - Tailscale 経由のとき（中継ヘッダーがあるとき）、パスコードが未設定なら、画面に「パスコードの設定を勧める」注意を出す（使えなくはしない）。
   - Cookie: HTTPS（X-Forwarded-Proto が https）で来たときは Secure を付ける。
3. **PWA（ホーム画面に追加できる形）**
   - `manifest.webmanifest`（名前、短い名前、アイコン、`display: standalone`、テーマ色は暗い背景と差し色の赤系）、アイコン（SVG から PNG を作るか、PNG を用意。180×180 の apple-touch-icon も）。アイコンは「赤い丸」を避ける（録音ボタンと紛らわしいとユーザーが指摘済み）。
   - Service Worker は最小限（アプリの画面ファイルのキャッシュのみ。音声や API はキャッシュしない。更新がすぐ反映されるよう版の付け方を工夫）。オフライン保存は T06b。
   - iPhone のノッチ・ホームバーを考えた余白（`viewport-fit=cover`、`env(safe-area-inset-*)`）。
4. **端末の診断ページ**
   - `/#/diag`（ライブラリから辿れるリンク。普段は目立たせない）で、その端末のブラウザについて次を調べ、結果を画面に出し、`POST /api/diag` でサーバーに保存（`data/diag/<日時>-<端末>.json`。DB に入れなくてよい）する。
     - UA、画面サイズ、standalone（ホーム画面から開いたか）
     - `decodeAudioData` できる形式: Opus/WebM（今の stream）、AAC/M4A、MP3、FLAC、WAV。それぞれ小さなテスト音声をサーバーが用意（ffmpeg で作ってキャッシュ）。
     - `<audio>` の `canPlayType` の結果
     - AudioContext のサンプルレート、outputLatency / baseLatency
     - メモリの目安（`navigator.deviceMemory` 等、取れる範囲）
     - Media Session API、Web Push（`PushManager`）、Notification、Service Worker、Cache Storage、IndexedDB、`navigator.storage.estimate()` の有無と値
     - 画面ロック中に音が止まるかを調べる簡単な試験（任意。ユーザーが操作して結果を記録する形でよい）
   - `GET /api/diag`（一覧）で監督役が結果を読めるようにする。
5. **doctor の追加**: Tailscale（入っているか、ログインしているか、serve の状態、名前）を「注意／OK」で出す。
